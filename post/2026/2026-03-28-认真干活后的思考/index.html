当然，最花时间的是解决了Cassandra cluster的 LDAPAuthenticator 的plugin安装测试。 原先的Cassandra multi cluster部署脚本是另外一名同事写的。 里面的配置，我一知半解。 原先我们图省事，Authenticator用的是PasswordAuthenticator。

用Cursor 和Claude Code来解决Mac Mini上的配置问题 3/28/2026

在自己的Mac mini上我也用cursor了。 今天早上我发现自己常用的Hugo命令生成的博客文件名字和title 日期都是2026年2月25打头。我怀疑是我的Hugo命令和.zshrc配置出了问题。 把问题敲入cursor的问答框，选用的是自动模式，问题发送后，cursor很快给我回复了答案。也帮我解决了问题。

~/.zshrc 里看到的

  • 第 24 行 source ~/.bash_profile：真正定义博客命令的是 ~/.bash_profile，不是 .zshrc 本身。

  • 安全风险（重要）：第 4–6 行把 OpenAI / DeepSeek 的 API Key 明文写进配置文件。任何能读你 home 目录的程序、备份或误提交的 dotfiles 都可能泄露。建议：

  • 在服务商控制台 轮换（revoke 并重建）这些 Key；

  • 之后改用例如 ~/.config/secrets.env（chmod 600）+ set -a; source …; set +a，且 不要把该文件提交到 Git。

  • 其余主要是 Oh My Zsh 模板配置，没有明显问题。

~/.bash_profile 里和 writeblog 相关的问题（已改）

之前的问题在这里，不是 .zshrc：

  1. DATE 只在登录/执行 profile 时算一次 → 终端开久了，writeblog 一直用旧日期。已改为在 writeblog 里用 $(date +%Y-%m-%d) 每次现算。

  2. gitpush / dpblog 用 alias “… $DATETIME …"：在载入 profile 时 $DATETIME 被展开写进 alias 字符串，等于 提交说明里的时间被“钉死”在开机那一次。已改成 gitpush() / dpblog() 函数，提交时用 $(date +%Y-%m-%d-%H-%M-%S)。

  3. 删掉了重复的 YEAR/DATETIME/HUGO_BLOG 导出，并把反引号改成 $(…)（习惯上更安全、易读）。

另外 newblog / typeblog 仍依赖登录时的 postname，若你长期不关终端，这两个也可能和“今天”不一致；若你常用它们，可以再改成和 writeblog 一样的函数写法。
